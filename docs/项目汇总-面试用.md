> 目标：让你和面试官聊 30~60 分钟不卡壳。每个模块都能展开讲 1~2 分钟，
> 每个"坑"都有原因 + 解决 + 收获。

---

## 1. 一句话介绍（电梯陈述）

> "TripAI 是一个 AI 智能旅行规划平台：用户输入目的地、日期、预算和兴趣，
> 后端用 DeepSeek + 专家规则知识库生成每日行程，再经过高德地图校验真实地点，
> 前端提供地图路线、按天天气、花费记账、一键导航和分享卡片。
> 全栈 Next.js + FastAPI，MySQL 存储，部署在阿里云函数计算，CI/CD 全绿。"

项目定位：个人全栈练手 + 求职案例，全流程低成本可跑通。

## 3. 功能模块（每个都能展开讲）

### 3.1 AI 行程生成（核心）
- 输入：目的地 / 日期 / 人数 / 预算 / 兴趣 / 旅行类型 / 随行人群 / 节奏
- 流程：专家知识库算消费等级 → 提示词注入规则 → DeepSeek 生成结构化 JSON → Pydantic 校验 → 高德 POI 校验真实地点 → 最近邻排序 → 规则评分（<62 分自动重试）
- **SSE 流式进度**：前端四步进度条（预算分析 → AI 规划 → 地点核对 → 生成方案），不干等

### 3.2 消费知识库（区别于纯调 API 的关键）
- 9 个数据文件：城市消费系数、四档消费等级（经济/舒适/高品质/奢华）、兴趣权重、天数节奏、季节价格、人群约束、城市×等级价格、标志性地点、汇总规则
- 核心原则：**预算代表消费能力，不是必须花完的钱**
- 公式：人均每日预算 = 总预算 ÷ 人数 ÷ 天数；有效预算 = 人均每日 ÷ 城市系数 → 查表定档
- 结果：消费画像、建议区间、预算分配（住宿/餐饮/交通/门票…）、日均预算

### 3.3 行程管理与地图
- 可折叠的每日行程卡片、增删/排序/改时间花费
- 高德地图：地点打点 + 路线连线 + 点击联动详情
- **一键导航**：地点卡片跳转高德 App 导航
- 地点详情：营业时间 / 电话 / 图片（高德 POI 详情懒加载 + 数据库缓存）

### 3.4 天气系统
- 高德天气接口：实时天气 + 按天预报（限 4 天窗口）
- 超过预报窗口自动提示"出发前 3 天更新"，用 AI 生成时天气兜底
- 30 分钟内存缓存，控制免费额度

### 3.5 真实花费记账
- 每笔：金额 / 分类 / 第几天 / 备注
- 行程内：预算 vs 已花费 vs 结余 + 进度条（超支变红）
- 个人中心汇总：累计预算 / 实际花费

### 3.6 分享卡片
- 上传背景图、拖动调整位置、一键下载 PNG（长按保存到相册）
- 卡片内容：标题、日期、人数、金额（可编辑）、天气、按天行程
- 公开分享页：免登录查看完整行程

### 3.7 用户偏好记忆（"越用越懂你"）
- 每次生成自动学习：兴趣 / 类型 / 人群 / 节奏 / 消费档位 / 常去地点
- 编辑时删除的地点 → 记为"不喜欢"
- 下次生成前把偏好压成一句话摘要注入提示词（省 token、可解释）
- 前端：创建页开关 + 个人中心查看/单独移除/一键清除

### 3.8 工程化
- PWA：手机添加到主屏幕独立使用
- 生成日志 + 提示词版本管理（`generation_logs` / `prompt_versions`）
- 后端 20 条自动化测试 + 前端类型检查，CI 全绿

## 4. 架构与关键数据流

```
浏览器 (Next.js)
  │  fetch / SSE
  ▼
FastAPI 路由层 (auth / trips / ai / places)
  │
  ├─ 专家知识库 (app/data/*) → 消费等级/预算分配/约束
  ├─ DeepSeek (streaming 生成行程 JSON)
  ├─ 高德 Web 服务 (POI 校验/详情/天气)
  ├─ SQLAlchemy → MySQL (用户/行程/地点/记账/偏好/日志)
  └─ 规则评分 → 不合格自动重试一次
```

AI 生成主流程（要能画出来）：
1. 创建 draft 行程
2. 读用户偏好摘要 + 知识库规则 → 拼提示词
3. DeepSeek 生成 JSON（约 20~60 秒）
4. Pydantic 校验 → 高德 POI 并行核对真实地点坐标
5. 消费等级/预算由规则库**覆盖** AI 输出（AI 只负责选地点）
6. 规则评分，低于阈值带反馈重试
7. 写库 + 生成日志 + 学习偏好
8. SSE 推送完成 → 前端跳转详情页

## 5. 数据模型（核心表）

- `users`：账号、密码哈希、昵称
- `trips`：行程主表（目的地/日期/预算/消费等级/预算区间/天气/评分…）
- `schedules`：每日地点明细（第几天/顺序/时间/花费/交通/推荐理由）
- `places`：高德 POI 缓存（名称/坐标/评分/人均花费/营业时间/电话/图片）
- `trip_expenses`：真实花费记账
- `user_preferences`：偏好记忆（各维度计数）
- `generation_logs`：生成日志（输入/prompt/AI 输出/结果）
- `prompt_versions`：提示词版本快照

## 6. 关键技术亮点（可深聊）

1. **SSE 流式进度**：后端线程池 + 队列，前端 ReadableStream 解析 `event: stage/result/error`；生成不再"死等"
2. **规则库 + LLM 混合**：预算/消费用确定性规则（可解释、省 token），地点用 LLM 生成（个性化），再用高德校验（真实）
3. **高德配额保护**：POI 结果入库缓存、天气 30 分钟缓存、详情懒加载——免费额度够用
4. **偏好记忆**：隐式学习 + 摘要注入，不把历史全量塞 prompt
5. **PWA + 移动端优先**：底部 Tab、安全区适配、离线壳
6. **可解释的评分系统**：预算匹配/兴趣匹配/路线合理/消费符合四维打分，不合格自动重试

## 7. 踩过的坑（面试官最爱问）

1. **MySQL 不支持 `NULLS FIRST`**（PostgreSQL 语法）
   - 现象：删除行程/记账列表报 500
   - 解决：去掉 `nullsfirst()`，MySQL ASC 下 NULL 本来就排最前
   - 收获：同一套代码要兼容多数据库，测试环境（SQLite）更宽容，真实环境才暴露
2. **阿里云 FC 默认域名强制下载网页**（`*.fcapp.run` 加 `Content-Disposition: attachment`）
   - 原因：FC 默认域名只适合 API，网页必须自定义域名（国内需 ICP 备案）
   - 解决：日常用局域网 + PWA，简历演示用 Vercel，后端保持 FC
3. **跨平台安装依赖**：本地 Python 3.14，FC 运行时是 3.10
   - 现象：部署后启动报 `ModuleNotFoundError: exceptiongroup`
   - 原因：pip 按目标版本选 wheel 时，依赖标记 `python_version<3.11` 按本地解释器判断，跳过了回退包
   - 解决：`pip install --platform manylinux2014_x86_64 --python-version 3.10`，并显式补装 exceptiongroup/tzdata/uvloop
4. **photos JSON 序列化**：DB 存 JSON 字符串，Pydantic 声明 list，行程列表直接 500
   - 解决：`field_validator(mode="before")` 统一解析
5. **国内访问 Vercel 超时**：不是代码问题，是网络；CI 用 GitHub Actions，托管选国内 FC
6. **本地代理软件拦截 localhost**：Clash 系统代理导致本地请求 502，测试/联调要绕过代理

## 10. 面试高频问答（预演）

**Q：为什么用 FastAPI 而不是 Django/Flask？**
A：FastAPI 原生异步 + Pydantic 请求/响应校验 + 自动生成 Swagger 文档；和 TypeScript 前端配合，类型边界清晰。练手项目追求开发效率和类型安全。

**Q：AI 生成的地点怎么保证真实？**
A：三层保障：① 提示词强制"只推荐目的地真实地点"；② 后端用高德 POI 搜索核对每个地点，坐标以高德为准；③ 校对率低自动带反馈重试。另外备选推荐给了用户自由度，不强塞。

**Q：预算为什么不直接均分？**
A：预算代表消费能力而非消费目标。系统按"人均日预算 ÷ 城市系数"定档（经济/舒适/高品质/奢华），再按档位比例分配住宿/餐饮/交通/门票，并留备用金；所以同样 3000 元在上海是经济型、在三四线可能升档。

**Q：SSE 流式是怎么做的？**
A：后端生成流程拆成阶段，每个阶段通过队列把 `event: stage` 推给客户端；生成完推 `event: result`。前端用 `fetch + ReadableStream` 按行解析。这样用户能看到"预算分析→AI 规划→地点核对→生成方案"，避免 30~60 秒无反馈。

**Q：偏好记忆会不会过度拟合？**
A：做了三个控制：① 摘要注入时明确"仅供参考，冲突以本次需求为准"；② 创建页有开关可关闭；③ 个人中心可单独移除/一键清除。冷启动时无历史则完全回退到表单输入。

**Q：遇到的最大的坑？**
A：部署相关的几个。最有代表性的是 MySQL 的 `NULLS FIRST` 语法——本地测试全绿，线上删除行程直接 500。教训是测试环境和生产环境的差异要主动覆盖，之后我会在 CI 里加真实数据库的冒烟测试。

**Q：为什么前端用 Next.js 而不是 Vite + React？**
A：需要 PWA、文件路由、部署为独立服务；Next 的 standalone 输出 + 环境变量注入（NEXT_PUBLIC_API_URL）让前后端分离部署很顺。而且移动端优先的页面大多是客户端渲染，Next 也能按需做 SSR。

**Q：成本控制怎么做的？**
A：高德免费额度靠三层缓存（POI 入库、天气 30 分钟、详情懒加载）；AI 只在用户主动生成时调用；服务器用 FC 按量付费，闲置即停；测试全部 mock，不消耗真实 API。

**Q：如果继续做，下一步做什么？**
A：① 行程导出（ICS 日历 / PDF）；② 多方案对比（经济/舒适/豪华同屏）；③ 用生成日志做 AI 效果评估，反哺提示词版本迭代；④ 上线前补错误监控（Sentry）和更完整的 E2E 测试。
